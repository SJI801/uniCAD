## 补 0.4：全约束草图的 UI（00:58）

0.4 的验收句是「开启后拖不动，改尺寸才动」。检查发现这句话有两个缺口，各补一个：

1. **「拖不动」原来只拦画布拖动**（`CanvasView` 里一个 `fullyConstrained` 判断），
   属性面板的数字框、左栏「应用到全部」、交点分解、工具（修剪）照样能改几何 ——
   那不是「只允许改尺寸」，是「只拦了一种改法」。现在关卡在 **store 的几何入口**上
   （`refusesGeometryEdit`，配 `shapeEquals` 只比形状不比外观）：`transformSelection` /
   `updateEntityById` / `splitAtIntersections` / 非尺寸的 `addConstraintAction`，以及
   工具的提交漏斗（`commandRewritesGeometry`：`update` 且形状变了，或**同时**删+建
   —— 修剪是「删原线 + 加两段」，只看 `update` 会漏掉它）。尺寸路径
   （`setDimensionAction` / `setConstraintValueAction` / 尺寸约束含锚点）一律放行；
   `__` 前缀的预览与回滚一律放行（拦下来画布会卡在预览位置）；外观（图层/颜色/线型）
   不拦；只新建或只删除的命令不拦 —— **锁的是形状，不是整张图**。

2. **「完全定义」原来在数学上不可达**：没有任何锚点约束，整张草图永远留着刚体平移
   （和转动）自由度，`dof` 到不了 0。新增内核约束 **`FixedX` / `FixedY`**（tag 15/16）：
   一条约束只带一个标量，所以钉一个点要两条；它与 `Horizontal`/`Radius` 完全同形
   （unary、无 `b`、线性残差 `p.x − value`），**wire 格式一个字节都没改**。前端把
   「固定」做成**一个动作**：钉住该图元的**每个具名点**（直线 2 点⇒4 条，多段线每个
   顶点，圆/椭圆 ⇒ 圆心），一次点击就能让一条线 `dof = 0`。锚点**永远不碰尺寸参数**
   （沿用内核 `size_driven` 铁律）：固定圆只钉圆心，半径仍由半径/直径尺寸驱动。锚点值
   是**世界坐标**，所以新增 `SIGNED_DIMENSIONS`（允许负值，原来三层都按 `> 0` 拒收），
   并加进 `ZERO_VALUE_DIMENSIONS`。画布上成对的锚点合并成一枚「锁定」徽章
   （`constraintBadges`），否则一根线糊四个 X/Y。

坑：`ConstraintKind` 是**穷尽 Record**（LABEL/GLYPH/TAG），加一个 kind 要同时补五张表；
`fixedX` **不在** `buildConstraints` 的 `UNARY_CONSTRAINTS` 分支里走——那个分支只认直线，
锚点要排在它**之前**（任意图元都能钉）。

验证：内核 81 个测试（+4：锚点让线 dof=0、拖走被拉回、只钉位置不改尺寸、改值驱动）；
前端探针 60 个（+9，`_probe_fully_defined.test.ts`）全绿；typecheck / build 通过。
**内核算了 wasm，要硬刷新**（Ctrl+Shift+R），否则浏览器跑的还是旧内核。

## 2026-10-13 画布闪烁修复（渲染节流）

根因：`dirtyRef` 到处被置 true 却**没有任何地方读它** —— 帧循环每帧无条件全画
（清屏 + 重镶嵌整幅图 + 重建栅格 + 重建批次），静止时也每秒 60 次全屏重绘。

改动（src/ui/CanvasView.tsx + global.css）：
1. 帧循环加脏检查；脏来源三处：store 订阅（任何字段变）、指针/滚轮/拖拽事件、
   window.__unicadPreview / __unicadToolAnchor 引用变化（工具走旁路，订阅看不见）。
2. 栅格缓存（key = view + 栅格设置）：平移缩放之外不重算，单帧最贵的一块。
3. 镶嵌缓存（key = doc 引用 + scale + kernelReady）：平移/hover/改选择不重镶嵌。
   kernelReady 必须进 key —— 否则首帧 TS 回退结果会被缓存到关页面。
4. 修 `rafRef.current % 30` —— 那是 rAF 句柄不是帧号；改用独立帧计数。
5. 帧异常不再「只报一次」：计数节流（第 1 次 + 每 60 次）打印，且出错保持脏重试。
   以前「闪一下空白」被静默吞掉最难查。
6. CSS：.hud-item 去掉 backdrop-filter（盖在 WebGL 画布上 = 每帧重新模糊一次，
   核显上是白烧的开销与闪屏诱因）；.canvas-host 加 contain: paint。

验证：npm run typecheck + npm run build 都过。**没有打开页面看实际效果。**
若仍闪：看控制台有没有「渲染帧异常（第 N 次）」——有的话是帧崩溃不是重绘频率。

## 2026-10-13 画布闪烁（第二路）：状态栏滚动条 → 画布 resize 清屏（浏览器实测定位）

上面那条修的是「不该画的帧也在画」。这一条是**另一条独立成因**，用真实浏览器量出来的
（Tabbit + Playwright 在页内打点，不改文档）：

**因果链（每条都有数字）**：状态栏 chip 的文字宽度比它自身宽 4px（`scrollWidth` 916 /
`clientWidth` 912，坐标读数每帧都在变宽变窄）→ `overflow-x: auto` 弹出横向滚动条 →
`.status-bar` 的 `offsetHeight` 27 → 37 → 它是 `.canvas-host` 的 flex 兄弟，画布高
508 → 498.1 → `ResizeObserver` 触发 `apply()` → `canvas.width/height` 被重新赋值 =
**WebGL 绘图缓冲重建并清空**。用户看到的是「画布频繁闪 + 画面整体上下跳 10px」。
70 秒慢速扫动实测触发 5 次；鼠标连续移动时坐标文字一直在变，于是反复触发。

**改动**：
1. `global.css` 的 `.status-bar`：`overflow-y: hidden` + `scrollbar-width: none` +
   `::-webkit-scrollbar{height:0;width:0}`。状态栏是一行 chip，滚动条在这里没有价值 ——
   藏掉它，高度就不再被内容宽度牵动（`white-space: nowrap` 必须留着，否则折行同样改高度）。
2. `CanvasView.apply()`：只在我们**取整后**的尺寸真的变了才 resize/store 写入/重绘
   （亚像素抖动本来会白白唤醒一次整帧重绘），并在 resize 之后**同步补画一帧**
   （新增 `drawNowRef`，由渲染循环填 `drawOnce`）—— 改 `canvas.width/height` 必然清屏，
   等下一个 rAF 补画意味着中间露一帧空白，那就是可见的闪。

**验证（同一套打点，前后对比）**：扫动鼠标 3 遍 → 状态栏文字变宽 38 次（触发源仍在）、
**状态栏高度变化 0 次、容器高度变化 0 次、canvas 宽高赋值 0 次**（修复前分别是 5 / 5 / 每次 2）；
真视口缩放时 `canvas.width` 赋值到第一笔 `drawArrays` 间隔 ~4ms，同一任务内完成（修复前要等
下一个 rAF，最长 16ms）。另外确认上面那条渲染节流是有效的：静止 2.5 秒 **0 次绘制**，
扫动时约 11 帧/秒。

教训：**「闪烁」不一定在渲染管线里**。这次是一条 CSS 溢出规则把布局高度改了 10px，
经由 ResizeObserver 变成 WebGL 表面重建 —— 从画布代码里怎么读都读不出来，
只有把 `host-height / bar-height / canvasWrites` 三条曲线同时打点才看得见因果。
量「闪烁」的正确姿势是数**事件**（清屏次数、尺寸赋值次数、DOM 变更次数），不是截图。

## 阶段 3 · 3.1 旋转特征（Revolve）落地

**为什么先做它而不是阶段 2 布尔**：ROADMAP「建议推进节奏」第 3 条把「2.1 只做差 +
3.1 旋转 + 3.2 孔」捆在一批，且阶段 3 标明「每项独立，可穿插做」；布尔自己标着
XL +「最容易烂尾」，旋转是 M 且与拉伸同构。

**内核 `mesh.rs::revolve`**：把「绕轴车削」化成「沿 θ 拉伸」——每个轮廓点映到
`(s, r)`（沿轴距离、到轴有符号距离），在这个坐标系里曲面就是一次沿 θ 的拉伸，
于是壁的绕序规则与 `extrude` **逐字相同**（CCW 归一化 + 外法线 = 边方向转 -90°），
端盖复用 `triangulate`，只有顶点映射不同。角度分辨率复用 `arc_segment_count`
（r_max 扮演圆半径）。`Option`：轮廓贴轴/穿轴 → None（建模错误，前端给句子）。

**两个坑（都被测试抓住）**：
1. **符号系统**：扫掠方向的符号不能靠「翻轴」实现——会被后面的「把 r 归正」那步
   翻回来，两次抵消（测试报「两个半球」）。正解：r>0 归一化时**同时取反角度**
   （`(d,a) ≡ (-d,-a)` 是同一实体）；负角度只影响**绕序**（叉积自动反向）与
   **端盖法线**，而径向壁的**法线不翻**（材料永远在半径小的一侧，与扫掠方向无关）。
2. **测试助手本身是错的**：`signed_volume` 按 3 浮动步长取三角形三个顶点，而顶点是
   **6 浮动**（位置+法线）→ 把法线当位置读，方箱体积算出 0。**先拿已知答案（方箱
   500）验助手**才定位到——「断言写错了就假红」的活例。

**镶嵌体积 ≠ 精确体积**：网格径向壁是弦不是弧，体积天然小 `segs·sin(Δθ)`
（45 段时 0.32%）。断言必须用镶嵌后的值，否则每个正确的网格都被判 0.3% 错。

**TS 侧**：`revolveMesh` 桥（+ 手写 `KernelModule` 声明，wasm-bindgen `--no-typescript`）；
`RevolveFeature.axis` 是**图元引用**（草图里的直线）——挪线即重车、删线即错误节点；
求值器 `evalRevolve` 六条错误守卫（含「轮廓与轴不在同一草图」的坐标一致性）；
`RevolveTool` 两次拾取 + 角度**按度输入、按弧度存**（负角度/超 360 拒绝）；
注册表别名 `REV`，工具栏自动出现（`TOOL_SPECS.map`）；
`RIBBON_AUTO_COLLAPSE_BELOW` 2280 → 2340；json 编解码补 rotate 分支（否则保存抛错）；
树面板参数列按种类取（高度 mm / 角度 °），图标与工具栏同字形。

**未验证**：旋转的端到端手动路径（画半个截面 + 一根中心线 → REV → 选轮廓 → 选轴 →

## 阶段 2 · 2.1 补齐「并 / 交」（三种 op 全部可算）

**内核**：`boolean(a, b, op)` 一个入口，三种运算只差「何时 invert / clipTo」——
`OP_SUBTRACT=0 / OP_UNION=1 / OP_INTERSECT=2`（与 TS 的 `BOOL_OP` 镜像，同 `TRIM_TAG` 的做法）。
FFI 从 `boolean_subtract_mesh(a,b)` 换成 `boolean_mesh(a,b,op)`；未知 op 返回空而不是 panic。

**空算子的集合代数**（重构里丢过一次，被测试抓住）：`A−∅=A`、`A∪∅=A`、`A∩∅=∅`，
以及 a 为空时的镜像。原来只写「union 返回 a」——把 A−∅ 也变成了空集（行为回归）。

**两个断言我自己写错了**：
1. 「并 + 交 = 两者体积」是错的；正确恒等式是 `|A∪B| + |A∩B| = |A| + |B|` 与
   `|A−B| + |A∩B| = |A|`（用两条一起断言，三条运算自洽才算对）。
2. 「共享面消失」不能查「有没有顶点在 x=10」——外表面的边缘顶点**本来就在** x=10；
   要查的是「有没有三角形整个躺在这个平面上」。

**TS**：求值器删掉非差拒绝，改为 op → 码映射 + 每个 op 一句「结果为空」的原因；
树行加行内 `<select>`（差/并/交）——运算就是这个特征的参数，一次编辑一步撤销；
字形随 op 变（⊖ ∪ ∩）；内核 101/101。
