## 真根找到了：polyline wire 格式不自界定 → 多段只出一段（10-12 10:40）

展博「依旧无法修剪三段」。重查发现上面「wasm 过期」只是表象之一，**真 bug 在 wire 编解码**：

- `kernel/src/ffi.rs` 的 `encode_prim` 把 polyline 编成 `[4, closed, x,y, …]`——**没有顶点数**。
  输入侧靠 TS 的 `counts` 数组界定每实体长度，所以输入没问题；但**输出侧**
  `trim_target` / `split_scene` 返回的 `[tag, count, …pieces]` 是纯拼接，**没有逐段长度**。
- TS `decodePieceRun`（core/trim.ts）polyline 分支只能 `while (c+1 < buf.length)` **读到缓冲区末尾**
  → 第一个 polyline 段把后面所有段的坐标全吞成自己的点 → 返回 1 段而不是 3 段。
- **内核单测全绿却抓不到**：单测直接调 `trim::trim`（拿 `Prim`），根本不经过 wire 编解码——
  这正是「测试通过≠项目没问题」的教科书案例。凡目标是一条**多段线/矩形**（polyline），
  被剪成 ≥2 段就中招；目标是直线时（tag0 定长）反而不触发，所以之前没暴露。

修法（根治，7 处对称改）：给 polyline 线格式加**顶点数** → `[4, closed, count, x,y, …]`，自界定。
- Rust `ffi.rs`：`encode_prim` 加 count；`decode_prim` case4 从 `buf[2]` 读 count（并 clamp 防越界）。
- TS `kernel.ts`：`encodedSize`=3+2n、`writeEntity` 写 count、`decodePrimitive` 跳过 count、
  `tessellateTS` 两处 `(cnt-3)/2` + `base=off+3`。
- TS `trim.ts` `decodePieceRun` case4：读 count，**只读 count 个点**，cursor 精确推进。
- split.ts 复用 `decodePieceRun`，一并修好。
- `constraints.ts` 用输入 `counts[i]` 界定，本就安全，未动。

新增内核回归测试 `decode_flat_run_of_two_polylines`（ffi.rs，内联 #[cfg(test)]）：
断言「整段平坦流里解第一段 polyline 只出它自己的顶点数、不吞第二段」——直接锁死这个洞。
`encode_decode_roundtrip_polyline` 同步更新为 `len()==3+2n`。内核 52 passed; 0 failed。
已 `npm run wasm` 重建。**展博须硬刷新（Ctrl+Shift-R）再用。**

教训（新增，比上一条更硬）：**「扁平 wire 数组」的每一段都必须自界定**，否则任何「读到末尾」的
解码器都会吞掉后续段。输入侧有 counts 不等于输出侧也有——两边必须各自闭合。凡「内核测试全绿但 UI 多段错」
先怀疑 wire 编解码，那层单测通常够不到。

## 紧接着挖出第二个多段线 bug：polyline_slice 顶点判据用错索引（10-12 10:47）

修完 wire 格式后，用**真实 wasm 二进制**端到端跑「多段线被两刀剪」，发现解码对了（2 段、cursor 精确）
但**几何是错的**：
- 段1 = (0,0),(10,0),(3,0)；段2 = (7,0),(10,0),(10,0) —— 跑到远端又折回来。

真根：`kernel/src/trim.rs` 的 `polyline_slice`，判断顶点是否「严格在切片区间 (d0,d1) 内」时写的是
`cum[i+1] > d0 && cum[i] < d1`——**第二个条件查的是段起点 cum[i]，而不是要压入的那个顶点 cum[i+1]**。
于是只要顶点所在的**那一段起点**在 d1 之前，就把**超出 d1 的远端顶点**也塞进切片。
正确：`cum[i+1] > d0 + MIN_PIECE && cum[i+1] < d1 - MIN_PIECE`。

同样**只影响多段线**（直线走 Line 分支、圆弧走 Arc 分支，都不经此函数），所以和 wire bug 一起，
共同解释了「多段线剪不对/剪不出多段」。改完 55 passed（新增 3 条：
`polyline_slice_keeps_only_interior_vertices`、`polyline_slice_of_first_half_does_not_run_to_far_end`、
`trim_polyline_between_two_cutters_keeps_two_clean_pieces`）。

**方法论收获（关键）**：内核单测（直接调 `trim::trim` 拿 Prim）两个 bug 都抓不到——
wire 那个在编解码层，几何那个要**端到端**才显形。真正把两个 bug 揪出来的动作是：
**用真实 wasm 二进制 + 真实 FFI 调用 + 自己写解码**跑了一遍端到端。以后内核改动验证，
「跑单测」不够，要「过一遍真实 wasm 的 FFI 端到端」。这一步不写测试文件（stdin 喂 node + 直接 import wasm pkg）。
