# 2026-10-10 — uniCAD 立项并完成首个可用版本

## 做了什么

从零搭建了一个浏览器端 2D CAD 绘图软件（uniCAD），技术栈按用户要求
TS + WASM：React 19 + TypeScript 5.7 + Zustand 5 + WebGL2 + Rust/WASM 几何内核。

## 交付内容

**Rust 内核**（`kernel/src/`，约 2500 行）
- `math.rs` — Vec2 / Aabb / Mat3（2×3 仿射）/ 角度与扫描工具
- `geom.rs` — LineSeg / Circle / Arc / Ellipse / Polyline / Prim 枚举
- `query.rs` — 精确求交（线线/线圆/圆圆/线弧 + 细分回退）、命中测试、测距
- `snap.rs` — 9 类 OSNAP 候选生成 + ortho/polar/grid 约束
- `ffi.rs` — wasm-bindgen 导出面（VertexBuffer / PointBuffer / SceneTessellator /
  pick / snap_query / fillet / transform / encode 等）
- **49 个单元测试**

**前端**（`src/`，约 20 个源文件）
- `core/` — 类型定义、FFI 桥、实体工厂、补丁式命令历史
- `render/` — 相机、WebGL2 批量线段渲染器、网格、样式、覆盖层
- `tools/` — 工具状态机（选择/直线/多段线/矩形/圆/弧/椭圆/测量）+ 注册表
- `state/` — Zustand store
- `io/` — 自有 JSON 格式 + DXF R12 导入导出
- `ui/` — Workbench / CanvasView / Ribbon / LeftPanel / RightPanel / StatusBar /
  快捷键

## 关键决策

1. **跨边界用扁平 f64 数组**而非 JsValue —— 一次调用打包整个场景
2. **复用 wasm 线性内存**做顶点缓冲，避免每帧拷贝
3. **wasm-bindgen 用 `--target web`** —— Vite 6 不支持 `bundler` 的裸 ESM wasm 导入
4. **补丁式撤销**（Command = Patch[]）而非全量快照
5. **工具只产出 Command，从不直接改文档**

## 工具链攻坚（耗时最多）

本机无 VS Build Tools，Git Bash 的 `link.exe` 遮蔽 MSVC 链接器，导致所有
Rust host build-script 编译失败。尝试过：rust-lld、lld-link、MSVC SDK 库路径、
GNU 交叉编译 host —— 全部走不通（缺 VC Runtime 的 `msvcrt.lib` 等）。

**最终解法**：装完整 GNU 工具链让 host = `x86_64-pc-windows-gnu`。
卡点在于 rustup 的 self-update 会让安装静默失败，必须 `RUSTUP_NO_SELF_UPDATE=1`。

同时遇到：`cargo test` 需显式 `--target x86_64-pc-windows-gnu` 才能在 host 上跑、
npm 漏装 `@rollup/rollup-win32-x64-msvc` 与 `@esbuild/win32-x64`（用
`--save-optional` 锁定）。

## 修掉的真实 bug

内核侧：
- `fillet` 圆心/切点计算错误（重写为角平分线法）
- 圆切线捕捉公式错误（改为 `center + r·(cos θ, sin θ)`）
- 圆垂足重复 push 同一候选点（改为近点 + 远点）

前端侧：
- `isKernelReady()` 非响应式，内核加载完成后 UI 仍显示"TS 降级"。
  改为 store 里的 `kernelReady` 响应式字段

# 2026-10-10（续）— 修复用户报告的运行时崩溃

## 用户报告

浏览器 console：
```
App.tsx:21 Uncaught TypeError: Cannot read properties of undefined (reading 'buffer')
at kernel.js:399:30
at SceneBuffer.run (kernel.js:393:29)
```

## 根因（两个独立问题叠加）

**1. `kernel().memory` 在 `--target web` 下不存在**

wasm-bindgen 的 `web` 目标**不导出** `memory` 对象（`memory` 只作为内部
变量挂在 `wasm` 对象上）。旧代码 `new Float32Array(kernel().memory.buffer, ptr, len)`
必然拿到 `undefined.buffer`。

**修法**：把「返回裸指针 + JS 侧包视图」改成「Rust 侧返回 `Vec<f32>` / `Vec<f64>`」，
让 wasm-bindgen 做一次整块 memcpy 到 JS 拥有的数组：
- `VertexBuffer::to_f32_array()` / `PointBuffer::to_f64_array()`
- `SceneTessellator::vertex_array()`
- 删掉 `KernelModule.memory` 与两个 buffer 的 `ptr` 字段

**2. `initKernel()` 是异步的，但渲染循环没等它**

`SceneBuffer.run()` 无条件调用 `kernel()`，而 `initKernel()` 尚未 resolve 时
`kernel()` 会抛异常 —— 从 `requestAnimationFrame` 里抛出，直接打断整帧。
更糟的是 wasm 一旦 trap，分配器状态被污染，之后每帧都 trap（复现时出现
**249 条完全相同的异常**）。

**修法**：
- 新增 `kernelOrNull()`，`run()` 在读不到内核时走**纯 TS 回退镶嵌器**
- 新增 `tessellateTS()` —— 与 Rust `Prim::tessellate` 逐分支对齐
  （同一套 sagitta 分段公式、同一套 strips 语义）
- `run()` 包 try/catch：一旦 wasm 抛错就丢弃句柄、本帧回退 TS，
  避免"一次 trap 污染后续所有帧"
- `dispose()` 改为幂等（StrictMode 双挂载会调两次）
- `CanvasView` 帧循环先排下一帧再绘制，并 try/catch（只报一次错）

## 顺带发现并修掉的 bug

**TS 回退镶嵌器 strips 索引算错** —— 我在全局 `vo` 游标上又叠加了
`indexBase`，导致 strips 变成 `0,2, 4,32, 60,72…`，而正确值是全局累积的
`0,2, 2,30, 30,42…`。顶点数据其实完全正确（误差 0），只有 strips 错。

**`arcSegments` 退化分支与 Rust 不一致** —— Rust 在 `radius <= 1e-9` 时返回
`max_seg`，我返回 2，导致 `r=0` 的圆两条路径顶点数不同（3 vs 513）。

这两个都是靠新写的 `verify-tess-parity.mjs` 逐顶点比对才暴露的。

## 新增验证手段

**教训**：之前只用 `--dump-dom` 检查 DOM 文本，从不驱动渲染循环，
所以渲染崩溃完全没被发现。

- `scripts/smoke-render.mjs`：CDP 直连无头 Chrome，加载**生产构建**，
  用合成鼠标事件在画布上真实绘图，再驱动 151 帧 rAF，收集 console 错误与
  未捕获异常。含**交错压力测试**（pointer 事件里的 snapQuery 与 RAF 里的
  tessellate 交替触发）。随机调试端口，避免连续运行冲突。
- `scripts/verify-tess-parity.mjs`：60 组用例（10 场景 × 3 tol × 2 maxSeg）
  逐顶点、逐 strip 比对 TS 回退与 WASM 输出，覆盖全部退化输入。
- 本机 `http_proxy` 会拦截 `127.0.0.1`，跑这些脚本需要
  `NO_PROXY="127.0.0.1,localhost"`。
