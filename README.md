# uniCAD

浏览器端 2D CAD 绘图软件。**TypeScript 前端 + Rust/WASM 几何内核 + WebGL2 渲染**。

所有几何计算（求交、捕捉、包围盒、变换、圆角、测距/测面积）都在 Rust 内核里完成，
编译为 WebAssembly 后供前端调用；前端只负责交互、状态管理和渲染。

---

## 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | React 19 + TypeScript 5.7 | 并发渲染 + 严格类型 |
| 状态管理 | Zustand 5 | 细粒度选择器，避免全量重渲染 |
| 渲染 | 自研 WebGL2 批量线段渲染器 | 单次 draw call 画完整张图纸，描边宽度与缩放无关 |
| 几何内核 | Rust → `wasm32-unknown-unknown` | 所有计算下沉，前端零几何逻辑 |
| 内核绑定 | wasm-bindgen 0.2（`--target web`） | 显式 `init()`，Vite 无需额外插件 |
| 构建 | Vite 6 | 快速的 dev server 与生产打包 |

这种话，只有把真实求解器跑起来才验得了。

> 有一整套无头浏览器验证脚本（镶嵌一致性、渲染循环、GL 越界、画布像素、描边连续性、

> 删除前的备份在 `.workbuddy/backup/verify-scripts-2026-10-11.tgz`。

删除脚本不等于删除结论。它们的产物是下面这些**架构约束**，其中几条属于「不这么写
就会静默出错、控制台一句报错都没有」的类型，改动相关代码时仍然适用：

- **几何正确性不能靠肉眼看缩略图。** 1.4 px 宽的斜线在缩放后的预览里看着就像虚线，
  轴对齐的长直线不会 —— 极易误判成「圆弧渲染断裂」。判断连续性要沿法线量宽度。
- **屏幕坐标是画布尺寸的函数。** 工具栏收拢一次就差 28 px，`zoomToFit` 的取景随之
  改变，硬编码的圆心量的就不再是那个圆，而报出来的症状是「描边断续」，看起来像
  渲染坏了。需要坐标时用模型坐标（`window.__unicadView` 可换算）。
- **无报错不等于画对了。** `LineTool` 曾经一次都没提交而提示一路正常走；着色器把
  模型坐标喂进错误空间时所有顶点挤到一个角落，栅格与像素占比看上去完全正常。
- **工具是连续的。** `LineTool` 落一点即提交一段、命令不退出，所以「画完再点一下
  把它选中」会再画一条线，症状表现为「选中不了」，像拾取坏了；线索只有图元数
  +2 而不是 +1。
- **布局契约用 DOM 几何就能证明**（收拢让出的高度是否精确、控件是否仍可达、下拉
  有没有被 `overflow` 裁），不必碰像素。

前端目前**没有任何自动化回归手段**。改动几何、渲染或布局相关代码时，请手动在两三
个画布尺寸、两三档缩放下各看一遍。


**文档模型（阶段 1 起）**：文档是一棵**特征树** —— `nodes` 有序，草图是图元的**唯一**宿主，
特征存意图（草图 / 轮廓 / 高度）而不存网格。两条铁律：

1. **几何计算全在内核**，前端零几何逻辑；`core/evaluate.ts` 只做编排（把意图喂给内核、
   把网格和错误收上来），不在 TS 里算三角形。
2. **「哪些图元」这个问题只有一个地方回答**：`core/doc.ts`。渲染、拾取、捕捉、约束桥、
   IO、面板全部走它的选择器（`sketchEntities` / `findEntity` / `allEntities` / …），
   没有一个模块自己遍历 `nodes`。所以「活动草图」这个概念的改法只动一个文件。

### 顶点缓冲为什么要「返回 Vec」而不是传裸指针

wasm-bindgen 的 `web` 目标**不导出**线性内存对象，所以 JS 侧无法把 Rust 给的
`ptr` 包成 TypedArray（旧代码那行 `new Float32Array(kernel().memory.buffer, …)`
必然拿到 `undefined.buffer`）。

正解是 Rust 返回 `Vec<f32>` / `Vec<f64>`（`to_f32_array` / `to_f64_array` /
`vertex_array`），由 wasm-bindgen 做**一次整块 memcpy** 到 JS 拥有的数组 ——
既正确，又远快于逐元素循环。

### 批次是**追加**的，每帧必须以 `beginLineBatch()` 开始

渲染器把整帧几何攒进**一个**批次，最后只发一次 `drawLines`：栅格、实体、
交互叠加层依次 `buildLineBatch`，先入批的在下层。

`buildLineBatch` 是追加语义（只上传本次新增的那一段，带字节偏移），因此
`drawLines` 画完会把游标归零，每帧开头还有一次显式的 `beginLineBatch()`。
这个约定必须显式，因为旧实现是**覆盖**语义 —— 一帧三次调用里前两次攒的几何
会被后一次直接顶掉，最终画面上只剩最后两批：**实体被栅格整批擦掉**。全程无报错。

### 相机变换只有一个来源：`clipMatrixOf`

`src/render/camera.ts` 里的 `clipMatrixOf(view)` 是模型 → 裁剪空间的**唯一**
实现，`Camera.clipMatrix()` 与渲染循环都从它取值。

它必须与 `Camera.worldToScreen` 逐符号一致 —— 模型空间 y 轴向上，翻转发生在
相机里：

```
screenX = (x - cx) / s + w/2      CSS 像素，原点在左上
screenY = h/2 - (y - cy) / s      模型 y 向上，翻转就在这里
ndcY    = 1 - 2 * screenY / h  ⟹  ndcY = +2 * (y - cy) / (s * h)
```

那个**正号**是全部要害。把 `screenY` 当成「模型 y 本来就向下」来读，符号就变成
负，整幅场景相对光标垂直镜像 —— 而**什么都不会报错**：每个图元照样光栅化、
每次缓冲上传照样通过校验，只是几何全都跑到光标的对面去了。

这个公式曾经有三份各自抄写的副本（`Camera`、`gl.ts` 的 `makeViewMatrix`、
`CanvasView` 里内联的一份），其中两份从未被调用、唯一在用的那份符号写反。
所以现在只剩一份，另外两处改为转发。

教训与前一条 `kernelReady` 同源：**同一个事实不要抄第二遍**，抄写的副本不会
跟着一起改。

### 描边几何：斜接接头 + 解析抗锯齿

线宽是**屏幕空间**的：顶点着色器把模型坐标先换算到 CSS 像素、加上法线方向的
偏移、再换回裁剪空间，因此缩放不影响粗细。围绕这一点有三条不能动的约定。

**一、一个线段 = 一个梯形，顶点带「该端点自己的」斜接法线。**

每个端点取相邻两段法线的角平分线，并乘上 `1 / cos(θ/2)` 的斜接补偿
（上限 4，防止近 180° 的尖刺飞出去）。两个后果缺一不可：

- 相邻梯形**共用同一条端边**：转弯外侧不留楔形缺口，内侧也不重叠；
- 直角拐角处线宽仍是 `2 * halfW`，而不是被压成 `2 * halfW * cos(θ/2)`
  （90° 角上就是窄 29 %）。

*只有一端有邻居*（开放折线的首尾）时**必须跳过补偿** —— 此时角平分线就是该段
法线本身，再乘一次系数会把线画成两倍宽。

**二、四边形的顶点布局必须让两个三角形沿同一条对角线剖分。**

```
k : pos      side
0 : 起点A    -1        A-
1 : 终点B    +1        B+
2 : 终点B    -1        B-
3 : 起点A    +1        A+
4 : 终点B    +1        B+
5 : 起点A    -1        A-
```

三角形 `(0,1,2)` 与 `(3,4,5)` 都以 `A- ↔ B+` 为对角线，并集才是整个四边形。

这里曾经写成 `k % 3 === 0 ? 起点 : 终点` 配 `k % 2 === 0 ? -1 : 1`。两个取模
表达式在 `k = 5` 上互相矛盾（位置取终点、侧向取 +1，但终点的那一侧必须是 -1），
于是第二个三角形退化成 `(A+, B+, B+)`，四边形**起始那一半永远没被光栅化**。
直线看不出来（每段独立、缺口被相邻段遮住），一条细分过的圆就成了周期等于弦长的
虚线。**几何正确性要靠 `--dump-verts` 抓真实顶点流来核，不能靠肉眼看缩略图。**

**三、边缘覆盖由片元着色器解析算出，不依赖 MSAA。**

顶点把「到中心线的带符号偏移」原样传给片元，覆盖率就是
`clamp((ext - |off|) / (2 * u_aa), 0, 1)`，`u_aa` 取半个**设备**像素。

原因是线只有 ~1.4 px 宽，一个像素的取整完全决定了「看起来多粗」。交给 MSAA
等于把结果交给多重采样点的落点：沿一条细分曲线，中心线的亚像素相位随弦方向
推进，覆盖率就在「一个实心像素」和「两个幽灵像素」之间来回摆 —— 实测同一圈上
表观宽度摆动 40 % 以上。把覆盖率变成几何的函数之后，粗细与角度、缩放、
采样点位置全都无关。

代价是**重叠即变黑**（alpha 混合会叠两次），所以第一条约定里的「共用端边」
不是可选项，是这条约定成立的前提。

> 顺带修掉的：`resize()` 曾经对背板尺寸取 `floor` 而 CSS 尺寸保留小数，
> 多出一像素差，浏览器于是把整块画布重采样一遍（≈0.2 % 缩放）。同上，
> 顶点流里也看不出来，只有把 `canvas.width` 和 `clientWidth` 一起打出来才发现。

### 尺寸标注：几何上 GPU，文字上 DOM

尺寸线（主线 + 端点刻度）是模型坐标的 `OverlaySegment`，并进和网格、图元完全
同一个 GPU 批次 —— 所以高亮和标注都不会触发重新镶嵌。但**文字不上 GPU**：
浏览器自己的光栅化器出的字比字形图集清晰得多、便宜得多，代价只是要维护一层
DOM。于是 `dims.ts` 是唯一同时产出「几何 + 文本」的模块，两个通道在这里汇合。

**文字层由渲染循环直接写 DOM，不走 React state。** 实时读数要跟着光标，也就是
每帧都变；为了移动一个 `<span>` 每秒重渲染这个 800 行的组件，是一次毫无意义的
协调开销。做法是一个 `<span>` 池：不够就长、多了就 `display: none`，只在内容
真变了的时候才碰 `textContent` 与 CSS 变量。位置走 `--dx/--dy` 两个变量，居中的
`translate(-50%, -50%)` 留在样式表里。

位置每帧取整到整数像素：亚像素位移会让文字每帧重新光栅化，糊成一团。

几个必须记住的换算与判定：

- **模型法向 → 屏幕方向只翻 y。** 模型 y 朝上、屏幕 y 朝下，且两个轴等比，
  所以法向映射到屏幕就是 `(nx, -ny)`，不需要重算。标注的偏移距离和刻度长度
  一律按**屏幕像素**给、再乘 `scale` 换成模型单位 —— 标注是给眼睛看的，它离
  图元的距离必须在任何缩放下都一样。
- **标签要夹进视口。** 否则标到边缘的图元会被 `overflow: hidden` 裁掉半个数字，
  而「差一点就能看见」比干脆不显示更让人抓狂。
- **朝向看整批选中对象的包围盒。** 单看一条边判断不出「外侧」（两侧完全对称），
  但把选中的这批对象当成「这个图形」，法向朝外的方向就定下来了 —— 否则矩形的
  左右竖边会把尺寸线画进内部、压在别的图元上，而每个数字本身都是对的。
- **覆盖层 `pointer-events: none`**，标注绝不能挡住画布的拾取与拖拽。

> 尺寸线几何本来在 `overlay.ts`（`measurementLeader`），这次搬进了 `dims.ts`。
> 它是唯一还要吐文字的 overlay，留在两处就会有两份会各自漂移的实现。

### GPU 缓冲的分配策略

顶点缓冲按容量增长，只有当前批次装不下时才 `bufferData` 重新分配（几何级数
增长）。两个原因：

1. **性能** —— 稳定场景下每帧零分配。旧实现每帧 5–8 次 `bufferData`
   （= 每帧重新申请显存），对共享显存的核显是显存抖动。
2. **正确性** —— 若驱动拒绝分配（显存不足 / 超过上限），缓冲会**静默保持旧
   尺寸**，随后的 `bufferSubData` 就会越界并打印
   `INVALID_VALUE: bufferSubData: buffer overflow`。现在分配失败会跳过本次
   写入并清除容量记录，下一帧重试，结构上不可能越界。


### 跨 FFI 边界的数据格式

实体以**扁平 f64 数组**传输，避免每帧的 `JsValue` 开销：

```
[kind, ...coords]
  kind 0 = 直线   [0, x1, y1, x2, y2]                        (5)
  kind 1 = 圆     [1, cx, cy, r]                             (4)
  kind 2 = 圆弧   [2, cx, cy, r, startAngle, endAngle]       (6)
  kind 3 = 椭圆   [3, cx, cy, rx, ry, rotation]              (6)
  kind 4 = 多段线 [4, closed, pointCount, ...(x, y) * N]     (3 + 2N)
```

多段线**必须自称顶点数**（`pointCount`）。打包输入场景时靠并行的 offsets 数组
也能界定每段长度，但拆解/修剪的返回是一串**纯拼接**的图元（`[tag, count, …pieces]`），
没有逐段长度；若多段线不报告自己的大小，解码器只能「读到缓冲区末尾」，于是第一段
把后面所有段吞掉 —— 目标是一条多段线/矩形、被剪成多段时，只剩一段。线/圆/弧是定长，
所以这个 bug 只在多段线上显形。见 `ffi.rs` 的 `encode_prim` / `trim.ts` 的 `decodePieceRun`。

整个场景打包成一个 `Float64Array` + 一个 offsets 数组，一次调用即可完成
批量拾取、批量求交、批量捕捉。

## 功能

### 绘图

直线、多段线、矩形、圆、圆弧（三点 / 两点+半径）、椭圆、标注测量。

直线（`L`）是连续绘制：**每点下一次就立即落一条线段**，所以点完第二点就能看到
线；回车 / 右键 / `Esc` 结束本次连续绘制，输入 `C` 从当前端点补一条回到起点
收口。每段各自成为一条独立图元，撤销一步即回退一段。

> 这个「每段立即提交」不是细节偏好：此前实现把整条折线缓存起来、只在回车时
> 一次性提交，而那条提交路径（`commitRun`）根本没有调用者，于是工具看着完全
> 正常 —— 提示一路在走、预览橡皮筋也在画 —— 却一个图元都不会产生。

### 自动尺寸

画布上实时显示尺寸，不需要手动去量。两条来源：

| 时机 | 显示什么 | 位置 |
|---|---|---|
| 绘制中 | 当前命令的实时读数：长度 / 半径 / 长短半轴 / 距离+角度 | 尺寸线外侧，跟着光标 |
| 选中时 | 每个选中图元自己的尺寸 | 画在该图元的尺寸线外侧 |

各图元标什么：

| 图元 | 读数 |
|---|---|
| 直线 | 长度 + 方位角 `120.0  ∠26.57°` |
| 多段线 | 总长（闭合的额外标 `(闭合)`）`Σ 173.514 (闭合)` |
| 圆 | 半径 + 直径 `R 14.0  ⌀ 28.0` |
| 圆弧 | 半径 + 圆心角 + 弧长 `R 20.5  154.64°  弧长 55.329` |
| 椭圆 | 长短半轴 `半轴 10.0 × 6.0` |

工具栏「尺寸」按钮或命令行 `DIM` 开关整组显示。默认开。

尺寸线一律画在图形**外侧**：单看一条边判断不出外侧（两侧完全对称），所以朝向
看的是**整批选中对象**的公共包围盒中心。框选几百个对象时最多标 40 条 —— 再密
下去就只剩糊屏，读不出任何东西。

> 这套读数是**交互态标注**，不是文档内容：不进撤销、不保存、不导出 DXF。
> 会随文件留存的那套尺寸标注（真正的 `DIMENSION` 图元）是另一件事。

### 几何约束与尺寸约束

工具栏「约束 ▾」里的**持久**关系。它们不是光标约束 —— 选中图元、加一条约束，
从此这些图元在任何后续编辑里都保持这个关系。分两族：**几何关系**（纯关系，9 种）
与**尺寸**（带目标值 —— 内核 8 个种类：6 个尺寸 + 锚点 `FixedX`/`FixedY`；前端菜单把
锚点合成一个「固定」动作，所以菜单一共 16 项）。

几何关系：

| 约束 | 作用于 | 说明 |
| --- | --- | --- |
| 重合 ⊙ | 两个有端点的图元 | 最近的一对命名点合并 |
| 点在曲线上 ∈ | 点 + 曲线 | 点的一侧必须是线性图元 |
| 相切 T | 直线+圆/弧，或两个圆/弧 | 解算开始时选定分支（内切 / 外切） |
| 垂直 ⊥ | 两条直线 | |
| 平行 ∥ | 两条直线 | |
| 同心 ◎ | 两个圆/圆弧 | |
| 等半径 = | 两个圆/圆弧 | |
| 水平 — / 竖直 ¦ | 直线（可多选） | 唯一支持多选的约束 |

尺寸（`0.1`）：

| 约束 | 作用于 | 说明 |
| --- | --- | --- |
| 距离 ↔ | 两个命名点 | 直线的**长度**就是它自己两端点的距离 |
| 水平距离 H / 竖直距离 V | 两个命名点 | 只钉一个轴，另一个轴自由 |
| 角度 ∠ | 两条直线 | 存**弧度**，面板按度输入 |
| 半径 R / 直径 Ø | 圆或圆弧 | unary，无伙伴 |
| 固定（锚点） | 任意单个图元 | 见下 |

**尺寸存的是目标值，不是显示出来的标注。** `Constraint.value` 就是意图，求解器把它
当残差一起解 —— 所以「标注两线距离 50 → 改成 80 → 图形跟着走」（`0.2` 改值即驱动：
属性面板、画布标注就地编辑、右栏约束列表三处写的是同一个值，而值**先落成约束**、
再驱动几何，于是它从此守得住，改别的尺寸、拖别的图元都不会把它带走）。

- **尺寸是唯一能驱动尺寸参数的约束。** 相切/平行这类关系**永远不改半径/半轴**
  （内核 `size_driven` 规矩）：相切残差里同时出现圆心、直线和半径，一旦半径是自由变量，
  最小范数步就会把半径和位置**平摊** —— 点一次「相切」，圆被改小了还挪了位置，用户看到
  的是「关系根本没生效」。想改尺寸就写尺寸约束。
- **「固定」（锚点，`0.4`）把该图元的每个具名点钉在当前位置**：直线 2 点 ⇒ 4 条约束
  （两端点各 x/y），多段线每个顶点，圆/椭圆是圆心。锚点值是**世界坐标**，所以可以是负数。
  它是**唯一**能消掉刚体平移（和转动）自由度的约束 —— 没有它，任何草图的自由度都到不了 0，
  「完全定义」就成了空话。锚点也**不碰尺寸**：固定一个圆只钉圆心，半径仍要半径尺寸驱动。
- **草图状态**（`0.3`）：状态栏 chip 报 `无约束 · N 自由度` / `欠约束 N` / `完全定义` /
  `过约束 · 冲突 N`（红色）。点一下把冲突项写进日志；打开「状态配色」后，还缺尺寸或方位
  约束的图元画成蓝色（只是位置没定的不染 —— 用「固定」钉住即可）。选中图元时，画布上还会
  画出它**还能动的方向**（十字箭头 = 可平移、「转」= 还能转、「尺寸」= 尺寸未定）。
- **「完全定义」是一把几何锁**（`0.4`）：打开之后**只允许改尺寸** —— 画布拖动、属性面板
  改坐标、变换/对齐、交点分解、几何关系约束、会改写已有图元的工具（修剪）全部拒绝并在
  日志里说明；改尺寸值与加尺寸/锚点约束、改颜色图层、新建与删除照旧。关卡放在 store 的
  几何入口（`refusesGeometryEdit`）而不是画布上：能改几何的入口不止拖动一个，只拦拖动的话
  属性面板照样能把刚锁住的线改走。判据用 `shapeEquals`（只比形状，不比图层/颜色/线型），
  所以锁的是**形状**，不是整张图。锁是**手动开关**，与自由度无关 —— 草图还剩多少自由度由
  状态芯片说。

行为要点：

- **存进文档**（`.unicad.json` 的 `constraints`），进撤销栈，删除图元时级联删除相关约束。
- **改完任何一边自动重解**。用户在属性面板改半径、或拖动夹点，求解器会把剩下的图元
  挪到满足约束的位置 —— 而且**一次撤销就能同时回滚「我的修改」和「求解器的修正」**
  （两者被合成同一条命令）。
- 菜单里不可用的项会**变灰并写出原因**（「相切需要『直线 + 圆/弧』或『两个圆/弧』」），
  而不是点了没反应。
- 画布上给约束打单字符徽章（可开关），悬停显示完整句子。徽章**只画涉及当前选中的
  约束** —— 一张三百条约束的图不该变成三百个徽章。锚点成对出现（x 一条、y 一条），
  所以同一个具名点上的一对被合并成一枚「锁定」徽章，否则一根线糊四个 X/Y。
- 属性面板「几何约束」一节列出所选图元涉及的约束，可单条删除或全部删除；尺寸行可以
  就地改值（改的是约束的目标值，不是几何）。

**DXF 不导出约束。** R12 没有约束表达，本项目导出的就是 R12 —— 约束是本项目自己
的语义，只存在于 `.unicad.json`。需要交换约束请用 JSON。

**求解器**（`kernel/src/constraints.rs`，Levenberg-Marquardt）：

- 目标是把残差降到 0，而不是「求一个解」。欠约束时阻尼让步长趋近最小范数解 ——
  用户没碰过的自由度**原地不动**，这比任何加权启发式都可靠。
- 雅可比用**中心差分**，不手推。十几个残差族手推就是十几次「大部分时候仍收敛」的
  符号错误机会。
- **分支在解算开始时选一次并固定**（直线-圆相切有两侧、圆-圆有内外切）。残差里的
  `|·|` 在 0 处不可微，圆心跨过直线时残差会跳 2r，有限差分会报出巨大斜率。
- 残差**归一化到长度量纲**（平行/垂直的余弦乘平均线长），否则正规方程严重病态。
- **阻尼是 `JᵀJ + λI`，不是 `JᵀJ + λ·diag(JᵀJ)`。** 后者不是各向同性的：零空间里的
  位移对 `λ` 不敏感，最小范数步会沿一个任意方向滑走。曾用「两点距离」量过 —— 拖动的
  21 个方向里有 8 个收敛到错误的位形（位移 (−21.6, −48.5)，正确值 (−36.0, −16.0)）；
  改成 `+λI` 之后 72/72 个方向都在 2 次迭代内收敛。

**拖动过程中也解算**（`__live_move`）：约束在拖动中就贴住几何，松手不再弹跳。每帧一条
LM 解算 —— 这里的系统很小（几十个变量），代价可以接受；其余 `__` 前缀的预览与回滚
**不解算**，预览阶段不动文档几何（`__revert_live_move` 必须能原样还原，否则画布会卡在
预览位置）。

### 编辑

补丁式撤销 / 重做（上限 500 步）、选择窗口（左→右为窗口选择，右→左为交叉选择）、
夹点拖拽、平移 / 旋转 / 缩放 / 镜像、偏移、圆角。

### 修剪（TR）

把被别的图元夹住的那一段剪掉。用法：**激活修剪工具，光标移到要剪掉的那一段上，
预览会用红色把那段整条画出来，确认无误再点一下**。右键或 Esc 结束。

支持直线、圆、圆弧、多段线。圆被剪一刀会变成圆弧（没有「整圆碎片」这种产物）。

- **一次点击 = 一步撤销。** 删除目标 + 新增剩下的所有段，在同一条 `Command` 里；
  分成两条命令会让一次 Ctrl+Z 只回滚一半。
- 剩下的每一段**继承目标的图层与线型/线宽/颜色覆盖**，所以剪完看起来和原来一样。
- 目标身上的约束会跟着级联删除（它已经不存在了）。
- **不支持椭圆。** 剪掉的椭圆是「椭圆弧」，本项目没有这种图元。与其悄悄退化成
  多段线（类型变了、属性面板对不上、DXF 也导不回椭圆），不如明说。
- 所有**可见**图元都是刀刃，所以不用先选边界；隐藏图层 / 冻结图层上的不算 ——
  否则会出现用户看不见的切点。

原理（`kernel/src/trim.rs`）：把目标图元归约成一个标量参数 `u ∈ [0,1]`（直线的
`t`、圆弧的归一化扫掠角、多段线的累计弧长），所有交点都是 `u` 上的点。排序后它们把
图元切成若干**区间**，点击落在哪个区间就删哪个、**其余全留**。按区间而不是「从 A 删到
B」是重复修剪能正常工作的原因 —— 被三个边界切过的直线，删掉一段后远处那几段还在，
而不是把最近两点之间的一切都清掉。

**切点只来自交点，且交点必在图元范围内。** 求交本身查范围
（`LineSeg::intersect` 要求 `0 ≤ t,u ≤ 1`，`Circle::intersect_segment` 卡
`-1e-9..=1.0+1e-9`），所以延长线交点、图元之外的交点都不会成为切点。

**点击作用于预览所画的那个图元、且在预览计算的那个位置。** 悬停时记录下被拾取到的实体
id，点击时直接用它，**不重新拾取**。十字交叉处两条线都落在拾取孔径里，而 `pick` 的答案是
「离光标最近的那个」—— 悬停与点击之间只要差零点几个像素，就可能拾取到另一条线，于是
**红色预览画的和实际被剪的不是同一个东西**。对破坏性工具来说这是最糟的失败方式。

位置同理：预览是在**上一次 move 节流点**算的，点击落点可以差几个像素；两点只要落在
交点两侧，内核就会选中隔壁区间 —— 红的画在中间段、剪掉的却是旁边那段。所以点击时
**沿预览的位置剪**（`hoverAt`），而不是点击落点。预览画哪，剪的就是哪。

### 偏置（O）

生成一条与原曲线**平行、间隔给定距离**的新曲线。用法：激活偏置 → **点要偏置的曲线**
→ 把光标移到要偏的那一侧，预览画出平行虚影 → 点一下落笔。右键或 Esc 结束；落笔后
**留在同一距离**上，可以连续偏置一串曲线。

- **距离两种给法**：先在命令行**输入一个数字**（如 `30`）锁定确切距离；不输则按
  **光标离曲线多远**决定 —— 拖出去点一下，快。
- **哪一侧由光标决定**，不写死符号。内核里 `+` 的方向是逐图元不同的（直线的 `+` 是
  它的左侧，圆的是**向外**，弧的也是向外）。工具同时算出 `+d` 与 `−d` 两条候选、取离
  光标更近的那条，省得把这张符号表在两处维护。
- 支持直线、圆、圆弧、多段线。**椭圆**走镶嵌，得到的是一条多段线 —— 椭圆的偏置不是
  椭圆，没有诚实的椭圆可返回。
- 新曲线拿到**全新的 id**（`offsetEntity` 重新发一个）；沿用源 id 会让文档里出现两个
  同 id 的图元，第二个拾取/撤销都碰不到。

### 特征树（左栏「特征」页）

文档的结构：**草图**（图元的宿主）和**特征**（由草图派生出来的东西），按列表顺序显示 ——
而那个顺序**就是求值顺序**，所以画在一起，而不是分成两组。内核能算的五种特征都在树上：
`⬒ 拉伸`、`◑ 旋转`、`⊖ 布尔`、`⊚ 孔`、`▦ 阵列`（字形与工具栏一致）。
草图是**图元的宿主**；特征由草图、**另一个特征**（布尔吃两个、阵列重复一个孔）或一次 3D 面拾取
（孔）派生。

- **点草图** = 切到它（活动草图 + 活动基准面），并回到 2D 视图 —— 你点一张草图的意思是要在它上面画东西。
- **点特征** = 在 3D 视图里高亮它（画成 2D 选中色那个琥珀色），并切到 3D —— 高亮只在 3D 里看得见。
- **双击名字**改名，**双击数值**改参数（拉伸高度 / 旋转角度）。两者都走「草稿 + 失焦/回车提交」
  的既有惯例：**一次编辑 = 一步撤销**，Ctrl+Z 一次回到原状，不留「打了十个字符要按十次撤销」的坑。
- **抑制**（⊘）：跳过求值，网格消失、节点变灰；取消抑制即恢复。**不是删除** ——
  节点还在，恢复后逐顶点与抑制前相同。
- **删除特征**（×）：只删节点，草图与图元都不动。
- **删除草图**（×）：会丢东西时**拒绝并说明**（日志里给原因），不级联、不静默：
  最后一张草图不能删（新图元没宿主）；草图里还有图元不能删（先把图元删掉）；
  被特征引用不能删（先删那些特征）。
- **红点 = 求值失败**：悬停看原因（轮廓被删、草图没了、轮廓不封闭、类型尚未实现）。
  同一个数字也出现在状态栏的「特征错误 N」里，点一下把每条原因写进日志。

### 3D 拉伸（X）

把一条**封闭草图**沿 +Z 拉成实体 —— 草图就是 2D 画布上画的东西。用法：按 `X`（或点工具栏
「⬒ 拉伸」）→ 点一条封闭轮廓（矩形 / 圆 / 闭合多段线）→ **输入高度后回车**。然后点视图组
的「看 3D」切到立体视角：**拖动旋转**，**滚轮推拉**，再点一次切回 2D（2D 的平移缩放原样保留）。

- 高度**用输入而不是拖**：拖只能精确到落点那一个像素，而「先画草图」的意义正是草图已经把
  零件的尺寸说死了。
- **参数化**：特征只存**意图** —— 草图 id + 轮廓 id + 高度（`ExtrudeFeature`，挂在特征树上）。
  三角网格由内核**每次文档变更现算**（`core/evaluate.ts`，全量重算、无增量图谱），
  改草图、改高度、抑制再恢复，实体都跟着变，什么都不用重烘焙。
- **特征不是 `Entity`**：`Entity` 是 2D 草图 —— 它进 wire 编码、被拾取、被属性面板编辑、被 DXF
  往返。特征这几样都不参与，所以它是树上的一个节点，那些 2D 路径一行没动。
- **删掉作为轮廓的那条曲线，会级联删掉由它拉出来的特征** —— 同一个命令，一次 Ctrl+Z
  连曲线带特征一起回来。
- 内核 `mesh.rs`：端盖用**耳切**三角化（凸多边形才敢上三角扇，L 形会溢出轮廓），侧壁每边两个
  三角、外法线朝外；输出**非索引**、每面一个法线的平面着色三角面片。**椭圆**走镶嵌成多段线。
- **半条曲线**（直线、圆弧）没有内部，拉不出网格：在特征树上显示为**红点**，悬停写着
  「轮廓不封闭或类型不支持」，状态栏同时报「特征错误 1」。以前这里是一个静默的空网格 ——
  「拉了个看不出来的实体」正是阶段 1 要消灭的失败方式。
- 一期**只有**「封闭草图 → 拉伸 / 旋转」：没有面拾取、没有布尔运算。

### 旋转（REV）

把一个**封闭草图**绕**同一张草图里的一根直线**车削成实体 —— 车床。用法：输入 `REV`
（或点工具栏「◑ 旋转」）→ 点封闭轮廓 → 点一根直线作为旋转轴 → **输入角度（度）后回车**。

- **轴是图元，不是坐标副本**：草图里的中心线就是一根直线，特征按 id 引用它。所以挪动那根线，
  实体跟着重新车削；删掉它，特征变成红点 —— 而不是默默绕着一个已经不存在的轴转。
- **轮廓必须整条在轴的一侧、且不贴轴**：穿过或贴住轴的轮廓扫出来会自我折叠，内核直接拒绝，
  报「轮廓不封闭，或轮廓穿过/贴在旋转轴上」。建模错误给句子，不给空网格。
- **度进、弧度存**：草图是模型单位，角度是人从量角器上读的东西。负角度朝另一边车；
  整圈（360°）**不封端盖** —— 闭合曲面再盖两张面等于往实体里塞重合的皮。
- 角度与高度的默认值都直接写在树面板那一行上，**双击数值即可改**（一次编辑一步撤销）。
- **内核里最微妙的一处是法线约定**：扫掠绕轴线右手方向；三角形**绕序**随扫掠方向自动翻转，
  而径向壁的**法线不翻** —— 壁的材料永远在半径小的一侧，与往哪边扫无关，只有端盖跟着翻。
  `mesh.rs` 的测试用**有符号体积**（散度定理）钉住这件事：体积为正 = 法线朝外。
  注意网格体积天然比精确车削**小 0.3%**（`segs·sin(Δθ)`）—— 径向壁是弦不是弧，
  这是镶嵌的必然，不是 bug，测试断言的是镶嵌后的值。

### 布尔（⊖ ∪ ∩，在特征树上）

把两个实体做布尔运算 —— **差**（打孔）、**并**（合并）、**交**（只留重叠）。用法：在左栏「特征」页
**点选被作用的那个特征（A）**，再点**另一个特征行上的 ⊖**：得到一个差集，命令行记一笔
`布尔差：拉伸 1 − 拉伸 2`。建好之后，那一行上的**下拉可以改成 并 / 交** —— 运算就是这个特征的参数，
改它和改高度一样是**一步撤销**。

- **两个算子都必须是它前面的节点**：树序即求值序，算子得先算完才轮得到布尔。新节点插在两个算子
  之后 —— 这条规则同时就是**无环的证明**（每个算子都在自己之前，引用链绕不回来）。
- **算子会被「消耗」**：它们的面已经成为结果的一部分，所以两行都变灰并标上「已消耗」，
  不再各自画出来 —— 否则你会看到一个壳套在另一个壳里。**求值失败的布尔不会消耗算子**：
  几何出错时，用户更需要看见的是那些几何，不是一片空白。
- **结果为空**是三种运算都可能出现的合法结局，各自有一句话说明原因（「B 把 A 整个盖住了」/
  「没有体积」/「没有重叠的部分」）—— 空画布不是答案。
- **结果是网格，不是 B-rep**：内核用 BSP 裁剪（Naylor 那套，csg.js 的三种写法）—— 几百行、
  无精确谓词、无需流形修复。代价写在明处：**共面面片靠容差活着**（容差按包围盒对角线取 `1e-6`，
  绝对容差在 100mm 和 0.1mm 的零件上不可能同时合适），退化情形仍可能出细长条；
  结果是三角汤不是流形 —— 画出来、再喂给下一个布尔都没问题，需要邻接关系的算法不行。
  `ROADMAP` 2.3 才是给退化情形做专项的地方。
- 三种运算的正式测试用**集合恒等式**钉住同一对实体：`|A∪B| + |A∩B| = |A| + |B|` 且
  `|A−B| + |A∩B| = |A|` —— 单独一条测对不算对，三条自洽才算。
- **退化输入有一张专门的表**（`degenerate_inputs_all_land_on_their_exact_volumes`，22 例）：
  部分共面、齐平口袋、切平顶面、完全重合（A−A / A∪A / A∩A）、面/边/角接触、
  「孔边在面内还是面外一微米」这一对、B 完全在 A 内、0.002 薄板、以及千分之一与一千倍两种尺度
  （验容差是相对的）。**每一条都是精确体积**，一次运行列出全部失败项 —— 健壮性收尾不该逐个试。
- **诚实说明**：这套用例证明的是「这 22 类给对了」，不是「所有退化都稳」。BSP 的容差分类在更刁的
  配置上仍可能出错；判据是**再遇到一类就往表里加一条**，而不是宣称已经没有退化问题了。

### 阵列（▦，在特征树上）

把一个孔**重复成一排或一片孔阵**。用法：在孔那一行点 **▦** —— 默认一排 3 个、间距 10，
四个数（两个方向的数量与间距）都在那一行上双击改。

- **实例是算出来的，不是复制出来的**：节点只存「源孔 + 两个方向各几个、各多远」，求值时
  **重新读源孔自己的参数**（位置、方向、⌀、深度）。所以改源孔的 ⌀ 或深度，**整排/整片孔一起变**
  —— 这正是特征级阵列存在的全部理由，也是它比「复制几何」强的地方（复制出来的那份不会跟着改）。
- **两个方向由内核定**：沿源孔所在面的**两条面内轴**，而这两条轴由面法线推出来
  （`perpendicular_basis`）—— 前端没有第二份「哪个方向算面内」的约定。第二方向数量填 1 就是一排，
  填 2 就是一片（四个安装孔就是把 1 改成 2）。
- **一次布尔，不是 N 次**：所有裁刀进**同一个**网格汤再做一次布尔差。N 次相减会让 BSP 反复面对
  越来越大的网格，同样的答案贵 N 倍。
- **退化的参数就地归一**：某个方向的数量 0/1 就是「一个」；那个方向的间距 0 让实例叠在一起，
  而 N 把重合的刀交给布尔只是自找退化 —— 这里直接当作一个；总数上限 1024（1000×1000 是手误）。
- 目前**只有孔**能被阵列（孔的四个参数完整描述了它落在哪）；圆周阵列是同一种节点上的更多字段，
  不是新的特征种类。

### 打孔（H，在 3D 视图里点面）

在实体表面上钻一个圆柱孔。用法：按 `H`（或点工具栏「⊚ 打孔」）→ **在 3D 视图里点一个面** →
孔就开在那儿（默认 ⌀5 通孔，两个参数在特征树上双击即改）。

- **点的是面，所以必须是 3D**：射线从相机穿过鼠标那一点（`screenRay`），与**可见的**网格求交
  （`pick_mesh`，内核里的 Möller–Trumbore）。命中给出三个东西：面上的点、那个面的**外法线**、
  以及**是被哪个特征的网格挡住的**——于是孔的轴自动垂直于你点的那个面，孔也自动记在正确的实体上。
- **只打可见的网格**：被布尔消耗掉的算子是隐藏的，所以射线点不到看不见的面。这一条规则就是
  「第二个孔会自动接着第一个孔的结果打」的原因 —— 你看到什么，就点得到什么。
- **裁刀在内核里造**：给定「面上一点 + 法线 + 直径 + 深度」，内核自己建坐标系、造圆、沿法线拉伸
  成圆柱、再做布尔差。前端不需要知道轴朝哪边、也不需要在哪儿多留一点余量 —— 那些约定只有一份。
- **深度 0 = 通孔**：通孔要多深才算出得去？按实体自己的包围盒算，而不是让用户猜一个数。
  孔的入口会从面向外**多切一点点**：切齐的话裁刀端面与实体表面共面，正是 BSP 容差最吃力、
  而孔口又最显眼的那种情形。
- **退化参数不崩**：直径 ≤ 0、法线为零、实体为空 —— 原样返回实体，前端在求值器里已经拦过一遍
  （「直径必须大于 0」）。
- 一期的孔**只有**「圆柱通孔/盲孔」：没有沉头、没有螺纹、没有阵列（3.6 的阵列会顺便解决最后一件事）。

### 基准面与参考坐标系

3D 的「画在哪儿」。左栏「基准」页管两样东西：

- **基准面**：XY / YZ / ZX 三个基础面，随文档自带、不可删。点**面名** = 设为活动草图面；
  点左侧圆点 = 在 3D 里显隐。
- **活动基准面**决定**新图元落在哪个面**：草图的 2D `(x, y)` 就是该面的局部 `(u, v)`，
  拉伸沿 `u × v`。2D 视图**只显示活动面上的图元**（别的面上的图元在这个视图里没有位置可言），
  拾取与框选一并过滤。
- **参考坐标系**：世界坐标系 + 可自建（「按活动面新建坐标系」，原点与两轴取自活动面）。
  3D 里画成红/绿/蓝三脚标（X 红、Y 绿、Z 蓝）。第三轴由 `xAxis × yAxis` 推出，写不出非右手系。
- 3D 里基准面画成**轮廓 + 面内两轴**，不画半透明填充：填充会和实体抢同一批像素，多个面相交时
  自身排序也会错；轮廓信息一样多，且从不遮挡。
- 3D 视图**有栅格**（铺在活动基准面上，间距随视距自适应）和**跟随鼠标的十字光标**：
  鼠标是一条射线，与活动面求交得到落点，状态栏给出该点在面局部坐标系的坐标 ——
  那正是画在这面上的草图会用的数字。
- **实体不存平面**：它从草图所属平面推出 —— 把草图换到另一个面，实体跟着走。
- **新建基准面**：选一个坐标平面（XY / YZ / ZX），沿它的法线偏移一段距离。基准面可以在
  「基准」页里点选，也可以**直接在 3D 视图里用鼠标点**——悬停会高亮那个面的轮廓，单击即把它
  设为新面的基准（拖拽仍是旋转，不会误选；命中的是画出来的那块面，点面旁空白不选任何东西）。
  派生面沿用基础面的两个轴，所以是严格的平行面。用户建的基准面可以删除；
  **面上还有图元、或面上的草图被特征引用时都会拒绝删除**（不级联、不让草图没地方画）。
  删掉一个面会连它的草图一起删（一个面 = 一张草图）；若删的正是活动面，「切回 XY」会并进同一条
  命令，一次撤销把面、草图和活动状态一起带回来。
- 一期的坐标系只作参考与摆放，**不参与绝对坐标变换**；三点定面 / 成角面还没做。

### 交点分解（EX）

**在交点处把图元自动打断**，AutoCAD 的 break-at-intersection。用法：选中若干对象后
点工具栏「修改 → 交点分解」，或在命令行输入 `EX` / `EXPLODE` / `SPLIT`。

- **作用范围看有没有选中**：有选中就只分解所选，没选中就分解**整幅活动草图**。这让它在
  DXF 导入之后能当「一键清理」用 —— 一张线互相穿过的图，点一下就都能单独抓了。
  （活动草图限定与渲染 / 拾取 / 修剪同一条规则：2D 视图只显示一个面，别的面上的图元在这个
  视图里连位置都没有。）
- 所选对象是跟**所有可见图元**求交切的，不是只跟所选之间切。常见需求是「这条线穿过了
  那堵墙，我想要墙里面那一段」，墙并不在被分解的对象里。
- **一次分解 = 一步撤销。** 5 个对象碎成 30 段也是一条 `Command`；分成 30 条意味着要按
  30 次 Ctrl+Z，而且半撤销状态是一堆与原图完全重合的重复线段 —— 看着像没变，最难查。
- 每一段**继承原对象的图层与线型/线宽/颜色覆盖**（名字不继承，两个同名实体比匿名更糟）。
- 原对象身上的约束**级联删除**，理由同修剪：它已经不存在了。
- 分解后**自动选中新生成的段**，因为原 id 已经失效。
- **椭圆不支持**，和修剪同一条理由：切开后的「椭圆弧」不是本项目的图元。单独选中一个
  椭圆按这个按钮，日志会明说原因而不是回一句「没有交点」。
- 隐藏 / 冻结图层上的对象不参与分解 —— 它们不是用户正在看的东西，分解完也没法再选中。

原理（`kernel/src/split.rs`）：**与修剪共用同一套参数化**。图元归约成 `u ∈ [0,1]`，交点
把 `u` 切成若干区间，每段 `slice` 出一个子图元；区别只是修剪丢掉被点击的那一段、分解
**全留**。共用是刻意的 —— 两套参数化迟早会在某个退化输入上给出不同的切点。

每个**无序对**只求交一次，把交点同时交给两侧，所以 N 个图元是 N²/2 次求交而不是每个
目标再重算一遍；外面还先做一次包围盒粗筛（混合类型求交会退化成对镶嵌化结果做线段求交，
大图纸上逐对都算会很贵）。

### 属性面板

选中对象后在左栏「属性」页签里列出它的**全部参数，每一项都能直接改** ——
包括几何尺寸。参数表由 `src/core/props.ts` 驱动，每个参数自带 apply，
所以「能不能改」就等于「这一行有没有 apply」；没有 apply 的行必须显式声明为
只读信息，忘写会立刻暴露，不会像早先那样整块几何静默变成只读。

| 对象 | 可改参数 |
|---|---|
| 直线 | 起点 / 终点 X·Y、长度、角度 |
| 圆 | 圆心、半径、直径、周长、面积 |
| 圆弧 | 圆心、半径、起始角、终止角、扫掠角、弧长 |
| 椭圆 | 中心、长半轴、短半轴、旋转角、面积 |
| 多段线 | 每个顶点 X·Y（最多 64 个）、顶点数、闭合、总长度 |
| 通用 | 图层、颜色、线型、线宽、名称 |

**派生量**（长度、角度、直径、周长、面积、扫掠角、弧长、总长度）由真正的自由度
算出，也允许直接改 —— 但要反解回那个自由度，规则写在每格的 tooltip 里，例如：

- 直线改**长度** → 固定起点、沿当前方向移动终点（不是缩放整条线）；
  改**角度** → 长度不变、绕起点旋转
- 圆改**直径 / 周长 / 面积** → 分别按 `v/2`、`v/2π`、`√(v/π)` 反解半径
- 圆弧改**扫掠角** → 固定起始角（限制在 (0°, 360°)，否则会退化成空圆弧）；
  改**弧长** → 固定圆心角、缩放半径
- 椭圆改**面积** → 等比缩放两条半轴，长短轴之比与旋转角不变
- 多段线改**总长度** → 以顶点质心为中心等比缩放，形状不变

其中**有对应约束类型**的那几行（直线的长度、圆的半径/直径、圆弧的半径）走的是
`0.2 改值即驱动`：敲进去的数**先写成尺寸约束**，几何与伙伴由求解器搬过去，于是这个
值从此有了身份。没有对应约束类型的（周长、面积、椭圆的半轴…）退回普通几何编辑 ——
值生效但守不住，下一次解算就可能被别的关系改回去。**「完全定义」锁着时这一点很关键**：
前者照常可用，后者会被拒绝并在日志里说明原因。

其余行为：颜色 / 线型 / 线宽支持「随层」（随层时显示图层上实际生效的值，点一下就
恢复继承）；多选时列出通用参数并一次应用到全部所选，**合并成一条撤销记录**；
取值不一致的显示「多值」占位。数值输入按草稿提交 —— 改一次就是一步撤销，
而不是每个字符一步；`Enter` / 失焦提交，`Esc` 撤销本次输入，`↑`/`↓` 按步长微调。

### 线型

实线 / 虚线 / 点线 / 点划线 / 中心线 / 隐藏线，图层与对象各自可设，对象覆盖图层。

图案按**屏幕像素**定义，所以它在任何缩放下都一样清晰；缩放只会让同样长的一段线
容纳更多周期。实现上没有把线切成小段，而是给每个顶点带上累计弧长和图案，由片元
着色器按 `mod(弧长, 周期)` 裁切 —— 因为斜接接头是在未切分的顶点序列上算的，
先切分会把每一段内部的接头变成两个平头端头。虚线的端头同样是羽化的：`discard`
会一次丢掉整个片元的所有采样点，MSAA 救不了它。

### 图层

新建 / 删除 / 重命名、可见性、锁定、颜色、线型（实线 / 虚线 / 点划线）、当前图层。

### 文件

- **自有 JSON 格式**（`.unicad.json`）—— 完整保存文档、图层与设置
- **DXF 导入 / 导出** —— R12 ASCII，支持 LINE / LWPOLYLINE / POLYLINE / CIRCLE /
  ARC / ELLIPSE / SPLINE / POINT，含 ACI 256 色调色板往返
- **PNG 导出** —— 从 WebGL 画布直接导出

文件格式是 **v2**（阶段 1 起）：文档是**特征树** —— `nodes` 里每个连接点要么是一张草图
（图元住在草图里，图元自身不再记平面），要么是一个特征（存意图：草图 / 轮廓 / 高度），
外加一个 `activeSketch`。

- **v1 文件自动迁移**：旧文件（一层扁平 `entities` + `solids` 边表）读入时按平面分组
  成草图、solids 转成拉伸特征，**读入即迁移到内存 v2，保存按 v2 写**，日志里会说明。
  迁移是幂等的 —— 同一份 v2 文件读两次不会长出第二张草图。
- **旧版本打不开新文件**（v2 的 `nodes` 对旧解析器不存在）。这是格式升级的代价，
  新版本读旧文件不受影响。
- **DXF 只认一张草图**：导入/导出交换的是**活动草图**（+ 图层与设置）。DXF 是扁平的 2D
  交换格式，别的基准面上的图元在一张图里没有位置 —— 导出时会写进头部范围的就只有活动
  草图，导入的图元也落进活动草图。**导入前想清楚你在哪张草图上**。

### 顶部工具栏的收拢

工具栏有两档高度，由最右端那个常驻的 ▴ / ▾ 按钮或 `Ctrl+F1` 切换：

| 状态 | 高度 | 内容 |
|---|---|---|
| 展开 | 62px | 七个带标题的分组：文件 / 交换 / 绘图 / 几何约束 / 修改 / 视图 / 捕捉与追踪 |

「几何约束」组里的 `约束 ▾` 菜单按 `CONSTRAINT_ORDER` 列出全部 16 项（9 关系 + 6 尺寸 +
`固定`），不可用的项变灰并把原因写在 tooltip 里；同一菜单末尾还有 `显示约束标记` 与
`完全定义（锁定拖动）` 两个开关，组内另有 `约束标记` / `端点标色` / `状态配色` 三个按钮
（状态配色与锁定见「几何约束与尺寸约束」一节）。
| 收拢 | 34px | 单行。去掉全部组标题，绘图工具变纯图标，文件 + 交换折成一个下拉 |

三条设计决定：

- **收拢不是「隐藏」**。绘图工具缩成纯图标方格（`title` 保留名称与命令别名），
  三个文字分组折进 `文件 ▾` 下拉。做到「一个控件都不少」，否则收拢态会变成
  一场找按钮的游戏。
- **约束与捕捉开关保留文字**。「正交」「极轴」「捕捉」猜不出图标，而点错一次
  会让接下来的标注静默跑偏 —— 这里省宽度不划算。
- **开关挂 `Ctrl+F1`（不是 F1）**。沿用的是 Office 的收拢和弦；裸 `F1` 归浏览器。

两个实现上的坑：

1. **收拢按钮必须 `position: sticky; right: 0`**。展开态是 ≈1850px 的控件，
   窄窗口下要横向滚动；如果按钮是普通 flex 子项，它会跟着滚出屏幕 ——
   唯一能把空间还回来的那个控件，恰好成了唯一够不到的那个。sticky 让它贴在
   滚动视口右缘，任何窗口宽度都在。不透明背景是必须的，否则控件会从底下透出来。
2. **下拉必须是 `position: fixed` 的兄弟节点**。`.ribbon` 是 `overflow-x: auto`
   的滚动容器，放进去会被裁成一条 34px 高的缝。坐标由触发按钮的
   `getBoundingClientRect()` 给出；菜单打开时要 `Escape` 并 `stopPropagation`，
   否则全局快捷键层会把同一个键读成「取消当前命令」。

顺带修掉的既有缺陷：`.osnap-row` 原本是 `flex-wrap: wrap`，而这条件栏是**定高
62px + `overflow-y: hidden`** 的 —— 换行的第二行不是「挤」，而是**看不见**，
连同下面的组标题一起被裁掉。而且 wrap 让内容不再溢出，`overflow-x: auto` 也就
从不触发，一个控件都不报错地消失。现在改为单行 + 横向滚动，横向溢出交给本来
就该承担它的滚动条。

首次访问（`localStorage` 里没有记录）时，视口宽度 < 1900px 直接给收拢态：
展开态放不下，与其给一条要滚动的工具栏，不如先收起来。用户的显式选择（点击或
`Ctrl+F1`）永远优先，并写入 `localStorage`（`unicad.ui.ribbonCollapsed`）。

## 本机工具链说明（Windows）

这台机器**没有安装 Visual Studio C++ 生成工具**，且 Git Bash 自带的 GNU `link.exe`
会遮蔽 MSVC 链接器，导致 Rust 在编译 host 端 build-script
（proc-macro2 / quote / wasm-bindgen-shared 等）时失败：

```
link: extra operand '....rcgu.o'
Try 'link --help' for more information.
```

解决方案是让 **host 端走 GNU ABI**，使用本机已安装的 MinGW-w64 GCC 16.1。
`.cargo/config.toml` 与 `scripts/build-wasm.mjs` 已自动处理，重现步骤如下：

```bash
# 1. 安装 GNU 工具链（host = x86_64-pc-windows-gnu）
#    注意：rustup 的 self-update 偶尔会让安装"看起来成功"但没落地，
#    报 `could not remove 'rustup-bin' file: 拒绝访问`。加 NO_SELF_UPDATE 规避。
RUSTUP_NO_SELF_UPDATE=1 rustup toolchain install stable-x86_64-pc-windows-gnu --profile minimal

# 2. 为该工具链添加 wasm32 目标
rustup target add wasm32-unknown-unknown --toolchain stable-x86_64-pc-windows-gnu

# 3. 安装 wasm-bindgen CLI（版本必须与 kernel/Cargo.toml 里的 wasm-bindgen 一致）
cargo install wasm-bindgen-cli --version 0.2.129
```

国内网络可加镜像加速：

```bash
export RUSTUP_DIST_SERVER="https://rsproxy.cn"
export RUSTUP_UPDATE_ROOT="https://rsproxy.cn/rustup"
```

> 如果日后装了 VS Build Tools，想切回 MSVC ABI：删除 `.cargo/config.toml`，
> 并执行 `rustup default stable-x86_64-pc-windows-msvc`。

### 关于 `--target web` 而不是 `bundler`

wasm-bindgen 的 `bundler` 目标会生成裸的 ESM wasm 导入：

```js
import * as wasm from './unicad_kernel_bg.wasm';
```

Vite 6 已不再支持这种写法，会报
`"ESM integration proposal for Wasm" is not supported`。因此改用 `web` 目标，
它导出一个显式的 `init(module_or_path)`，前端配合 Vite 的 `?url` 导入即可：

```ts
const [pkg, wasmUrl] = await Promise.all([
  import('@wasm/pkg/unicad_kernel.js'),
  import('@wasm/pkg/unicad_kernel_bg.wasm?url'),
]);
await pkg.default(wasmUrl.default);
```
